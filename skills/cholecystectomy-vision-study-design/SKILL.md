# 담낭절제 수술영상 연구 설계 (Metrics Reloaded 기반)

> 범용 버전: 다른 수술은 `/surgical-cv-study-design`. 이 스킬은 그 범용 스킬의 담낭절제 전용 심화판이며,
> `references/metrics_reloaded_core.md`는 범용 스킬과 같은 내용의 사본이다(수정 시 양쪽 동기화).

목표: 수술영상 AI 연구를 **"어떤 지표가 유행하나"가 아니라 "이 임상 질문의 성질이 무엇인가"에서 출발해**
설계한다. 산출물은 프로젝트 폴더의 `study_design/surgical_vision_design.md` 한 문서다(양식:
`references/design_template.md`).

## 원칙 (어기면 설계 실패)

1. **질문 하나 = 권고 하나.** 한 데이터셋에 임상 질문이 여러 개면(예: phase 인식 + 기구 분할) 각각 따로
   fingerprint와 지표 묶음을 만든다. 다중 라벨(기구 7종 존재 여부)은 라벨별 이진 문제로 쪼갠다.
2. **문제유형부터 맞춘다(S1, P1 함정).** 같은 종류 구조물이 한 화면에 여러 개 나올 수 있으면(파지기 2개 등)
   semantic segmentation이 아니라 instance segmentation 또는 object detection으로 정의한다. (SemS로 두고
   거리기반 지표를 쓰면 엉뚱한 개체 경계와 비교되는 오류 — 함정 논문은 이 그림을 P2.4로 분류.)
3. **단일 지표 금지, 주지표는 질문당 하나.** 겹침(overlap) 지표에는 경계(boundary) 지표를, 판별
   (discrimination)에는 보정(calibration)을, 고정 임계값 지표에는 다중 임계값 지표를 짝짓는다. 그중
   **질문(Q)마다 주지표(primary) 1개**를 사전 지정하고 나머지는 부지표. 구조가 여럿이면 주지표를 구조별로
   두되 다중성(multiplicity)을 설계서에 적는다. Dice와 IoU(사례별 단조관계), Sensitivity와 Recall(동일
   공식)을 둘 다 넣어 "보완"했다고 하지 않는다.
4. **분석단위는 환자/수술.** 인접 프레임은 강하게 상관되어 독립 표본이 아니다(FP4.5). 분할은 환자(수술)
   단위, 신뢰구간은 **환자(수술) 단위 cluster bootstrap**(또는 GEE·혼합모형 — MR의 "계층구조 존중" 원칙).
   지표 계산 단위는 지표 종류에 따라 다르다:
   - 분할·검출 지표(DSC, NSD, AP 등): 프레임(이미지)별 계산 → 비디오별 평균 → 비디오 간 집계.
   - 분류 지표(AUROC, AP, 보정): 비디오 안에 양·음성이 충분할 때만(예: phase, 기구 존재) 비디오별 계산 후
     평균. 수술당 판정이 1개이거나 비디오 내 한 클래스뿐이면(예: CVS 달성) **사례를 풀링해 계산하고 CI만
     cluster bootstrap**. 어느 방식을 쓰는지 설계서에 명시.
5. **빈 정답/빈 예측 규칙을 미리 쓴다.** 수술영상은 기구·구조물이 안 보이는 프레임이 많다(FP4.6, FP5.2).
   NaN 처리 규칙을 사전에 명시한다(`metrics_reloaded_core.md` §5). 빈 정답이 흔하면 **2층 평가**: (a) 모든
   프레임에서 존재 판정(AUROC/AP, 빈 정답 프레임 오탐률), (b) 정답에 구조가 있는 프레임에서만 분할 지표.
   정답·예측 모두 빈 프레임은 (a)에서 정답, (b)에서 제외(NaN→최악값을 그대로 쓰면 올바른 빈 예측이 0점).
6. **테스트 프레임은 실제 사용 분포를 따른다.** 구조물이 보이는 프레임만 골라 주석·평가하면 정밀도가
   부풀고 오경보율이 숨는다. 빈 프레임을 포함해 연속 구간 또는 무작위 표본을 평가한다.
7. **정답(reference) 품질을 숫자로.** 주석자 수·자격·판정(adjudication) 방식, 주석자 간 일치도를
   설계 단계에서 계획하고, 결과 자릿수는 주석자 간 변동을 넘지 않게 한다(0–1 척도 지표는 보통 소수 둘째
   자리, % 표기는 정수–소수 첫째 자리 이내; 일치도가 낮으면 더 줄인다).
8. **누설(leakage)과 시점을 정의한다.** 판정 시점이 있는 과제(CVS: 클립 적용 직전 등)는 시간 기준점과
   창(window)을 정하고, 정답을 암시하는 단서(클립 어플라이어가 보이는 프레임 등)를 평가 입력에서 배제한다.
   결국 실시간으로 쓸 계획이면 **지금부터 인과적(online) 설정으로 평가**하고, 프레임 처리량(≤ 1000/fps ms)과
   임상적 경고 지연(사건→경고 허용 시간, `[결정 필요]`)을 구분해 둘 다 정한다.
9. **Metrics Reloaded 범위 밖은 범위 밖이라고 쓴다.** 시간적 일관성(phase 전환), 회귀(술기 점수),
   추적(tracking), 퍼지/다중 관찰자 정답 생성(Go/No-Go, CVS 판정의 합의 정답 포함)은 이 프레임워크가
   다루지 않는다. `surgical_task_map.md` §3의 대체 근거를 쓰고 그 사실을 설계서 한계에 적는다.
10. **수치를 지어내지 않는다.** NSD 허용오차 τ, IoU 임계값, 표본수, 유병률 등은 임상 근거나 파일럿으로
   정하고, 근거가 없으면 `[결정 필요]`로 남긴다.

## 워크플로

### Step 0 — 입력 확인
사용자에게서(또는 프로젝트 파일에서) 다음을 확보한다. 없으면 한 번에 묻는다.
- 수술 종류·플랫폼(예: da Vinci SP/Xi, 복강경), 기관 수, 비디오 수·길이, 프레임 샘플링(fps)
- 임상 질문(이 AI가 무엇을 도와야 하나: 교육, 실시간 경고, 술후 품질평가, 결과 예측 …)
- 사용 시점: **online(실시간·인과적, 미래 프레임 사용 불가)** vs **offline(수술 후 전체 비디오)**
- 정답 형태: 프레임 라벨 / 구간(segment) / bbox / 마스크 / 점
- 물을 수 없는 상황(비대화형 실행)이면 합리적 가정을 세우고 설계서 §11에 `[결정 필요]`로 모두 적는다.
- 사용자가 다른 출력 경로를 주면 그 경로를 쓴다.

### Step 1 — 과제 분해와 문제유형 매핑 (S1)
`surgical_task_map.md` §1 표로 각 임상 질문을 ImLC / SemS / ObD / InS 또는 "범위 밖"으로 매핑한다.
매핑 근거(왜 SemS가 아니라 InS인지 등)를 한 줄씩 적는다.

### Step 2 — Problem fingerprint 작성
`metrics_reloaded_core.md` §2의 FP 항목을 질문별로 TRUE/FALSE/값으로 채운다. 수술영상 기본값은
`surgical_task_map.md` §2에서 시작하되 **반드시 이 연구 데이터로 확인**한다(예: 실제 빈 프레임 비율,
구조물 크기 분포, 주석자 간 변동).

### Step 3 — 지표 선택 (Step 2 of Metrics Reloaded)
문제유형별 경로(`metrics_reloaded_core.md` §3–4)를 따라 지표 묶음을 만든다.
1. 공통 참조기반 지표(위 경로) → 2. 응용특이 지표(clDice, 부피오차 등; 구간·이벤트 같은 시간적 지표는
MR 범위 밖이므로 외부 근거로 추가) → 3. 비참조 지표(추론 속도 fps·지연시간·메모리 — 실시간 수술 보조라면 필수).
작은 구조(담낭관·동맥·기구 끝)는 DSC가 몇 픽셀 차이로 크게 흔들리므로(P2.2) 경계·검출 관점 지표를 함께
두고 크기별 층화 결과를 보고한다. Net Benefit은 확률 임계값에 따른 **실제 의사결정**이 있을 때만 쓴다
(감사·연구 목적 판정에는 해당 없음).
지표마다 "어떤 FP 항목 때문에 골랐는지"를 표에 남긴다. 선택이 갈리는 지점(DSC vs IoU, AUROC vs AP,
NB vs EC)은 결정 근거를 적는다.

### Step 4 — 지표 적용 계획 (Step 3 of Metrics Reloaded)
- **구현:** MONAI MetricsReloaded 참조구현 사용, 버전 고정.
- **집계:** 프레임→비디오→전체 계층, 클래스별 보고 + 다중클래스 요약, NaN 규칙, 크기별 층화(FP3.2).
- **편향:** 기관·플랫폼·술자 경험·수술 난이도(염증 등) 메타데이터로 하위군 성능.
- **순위/비교:** 모델 비교는 같은 환자 단위 paired 분석, 순위 불확실성 표시.
- **보고:** 원시 지표 분포 시각화(박스플롯만 X → 점/바이올린), 혼동행렬 전체, 여러 seed/run의 변동,
  모든 지표에 95% CI.

### Step 5 — 데이터·주석·분할 설계
- 주석 체계: SAGES 주석 프레임워크(시간 계층: 수술 > phase > step > task > action) 용어에 맞춘다.
- 주석 프로토콜 문서화(정의·예시 프레임·경계 규칙), 주석자 ≥2명 일부 이중주석으로 일치도 산출.
- 분할: 환자/수술 단위, 가능하면 기관·플랫폼 단위 외부검증(leave-one-center-out). 단일기관이면 시간적
  분할(temporal validation, 뒤 시기 수술을 테스트로)을 쓰고 외부검증 부재를 한계로 명시한다. 술자·기관
  수가 적으면(예: 2명) 그 단위의 leave-one-out이나 cluster bootstrap은 무의미 — 하위군 기술통계로만 제시.
- 2D 영상의 거리·NSD τ는 픽셀 단위이고 줌·거리에 따라 실제 크기가 변한다. 해상도를 고정하고, τ는 이중주석
  프레임의 주석자 간 경계거리에서 도출하고, τ 민감도 분석(여러 τ)을 계획한다. 담낭관처럼 폭이 몇 픽셀인
  구조는 clDice를 주지표 후보로.
- 테스트셋은 개발 중 열람 금지, 임계값·후처리는 개발/튜닝 데이터에서만 결정.

### Step 6 — 설계서 작성과 점검
`design_template.md` 양식으로 설계서를 쓴다. 마지막에 아래 **레드플래그 점검**을 돌려 결과를 표로 붙인다.

| 코드 | 레드플래그 |
|---|---|
| RF1 | 프레임 단위 무작위 분할 / 프레임을 독립 표본으로 CI 계산 |
| RF2 | 분할 과제에 Dice(또는 IoU)만 — 경계 지표 없음 |
| RF3 | 같은 클래스 다중 개체인데 SemS로 정의 + 거리기반 지표 사용 |
| RF4 | 검출 과제에 Accuracy/Specificity/AUROC (TN이 정의되지 않음) |
| RF5 | 불균형 분류에 Accuracy 단독 헤드라인 |
| RF6 | 예측 확률이 의사결정에 쓰이는데 보정(calibration) 평가 없음 |
| RF7 | 빈 정답/빈 예측 처리 규칙 미기재 |
| RF8 | 주석자 간 일치도 계획 없음, 또는 소수점 자릿수가 일치도보다 정밀 |
| RF9 | 시간축 과제(phase·이벤트·CVS 시점)인데 online/offline 미명시, 시간 기준점·창 미정의; phase면 구간(segmental) 지표 없음 |
| RF10 | 실시간 사용 목적(장래 포함)인데 인과적 평가·추론 속도·지연 미평가 |
| RF11 | 임계값·후처리를 테스트셋에서 결정 |
| RF12 | 외부검증 없음 + 그 대안(시간적 분할)과 한계 기술도 없음 / 기관·플랫폼 하위군 계획 없음 |
| RF13 | 범위 밖 과제(회귀·추적·시간적·다중관찰자 정답)를 Metrics Reloaded 근거로만 정당화 |
| RF14 | 정답을 암시하는 단서(클립 어플라이어 등)가 평가 입력에 남음 |
| RF15 | 테스트 프레임을 "구조가 보이는 프레임"만으로 선별 |
| RF16 | 수술당 판정 1개인 과제에 비디오별 AUROC/보정 계산(정의 불가) |

### Step 7 — 넘겨주기
- 지표 계산·검증: `/model-assessment` (설계서의 지표표를 입력으로)
- 보고 체크리스트(CLAIM 2024, TRIPOD+AI, DECIDE-AI, IDEAL 등): `/check-reporting`
